# 판매·매출 종합 대시보드

전자랜드 상품팀 · 일보DB 기반 판매/매출 실적 조회 대시보드 (최근 5년)

**현재 상태** **실 데이터 반영 완료** — 일보DB 2022~2026년(최근 5년) + 기초DB 집계 결과가 들어 있습니다.

ㆍ`index.html` 은 **58KB** 로 가볍고, 데이터는 `data/` 폴더에서 필요한 만큼만 불러옵니다.
ㆍ**반드시 웹서버(GitHub Pages 등)를 통해 접속**하십시오. 파일을 더블클릭해 여는 방식(`file://`)은 브라우저 보안정책상 데이터를 읽지 못합니다.

> **로컬 확인** 저장소 폴더에서 `python3 -m http.server 8000` 실행 후 `http://localhost:8000` 접속

## 1. GitHub 업로드 및 배포

### 1-1. 업로드 (권장 — Git 사용)

웹 화면에서 파일을 끌어다 놓는 방식은 **파일당 25MB 제한**과 다중 업로드 실패가 잦으므로 Git 사용을 권장합니다.

```bash
git clone https://github.com/{계정}/{저장소}.git
cd {저장소}
# 압축을 푼 파일들을 이 폴더에 복사
git add .
git commit -m "판매매출 대시보드 배포"
git push
```

### 1-2. 웹 화면으로 업로드하는 경우

`Add file → Upload files` 에서 **한 번에 전부 올리지 말고 나눠서** 올리십시오.

1. `index.html`, `README.md`, `.nojekyll` 먼저
2. `tools/` 폴더
3. `data/` 폴더의 파일을 **3~4개씩 나눠서**

> 모든 파일이 11MB 이하라 개별 업로드는 가능하지만, 한 번에 여러 개를 올리면 합계 용량 때문에 실패할 수 있습니다.

### 1-3. 접속 비밀번호

접속 시 비밀번호 입력창이 뜹니다. **`100608`**

> 정적 페이지 특성상 클라이언트 측 검증이라 강한 보안은 아닙니다. 외부 노출을 막는 최소 장치이며,
> 같은 브라우저 세션 중에는 재입력을 요구하지 않습니다. 변경하려면 `index.html` 의 `var GATE_PW='100608';` 를 수정하십시오.

### 1-4. Pages 활성화

**Settings → Pages → Source: `main` / `/ (root)`** 선택 후 1~2분 뒤 `https://{계정}.github.io/{저장소}/` 접속

> 사내망에서 GitHub 접근이 어렵다면 사내 웹서버에 같은 폴더를 올려도 동일하게 동작합니다.

## 3. 데이터 구조

용량 문제로 큐브를 둘로 나눴습니다.

| 파일 | 그레인 | 크기 | 로드 시점 |
|---|---|---|---|
| `core.json` | y·m·판매구분·채널·그룹·품목·거래선 | 6.2MB (gzip 1.4MB) | **접속 시 1회** — 상품축 + 최근5년 추세 담당 |
| `year_{연도}_{H1\|H2}.json` | 위 + **지점** | 5.7~11MB (gzip 1~1.8MB) | **조직축 선택 시** 해당 기간만 |

원본 3,271,975행을 한 파일로 만들면 **170MB**라 브라우저에서 열 수 없습니다.
지점(store) 차원이 용량의 대부분을 차지하므로 코어에서 분리했고, **GitHub 업로드 제한(파일당 25MB)** 을 고려해 반기 단위로 나눴습니다.

ㆍ상반기만 조회하면 H2 파일은 받지 않습니다
ㆍ같은 기간은 최초 1회만 로드되고 이후 캐시됩니다
ㆍ전년·전전년 비교를 위해 3개 연도를 함께 불러옵니다

> 큐브를 차원 기준으로 더 쪼개면 `품목 필터 + 거래선축 + 지부 필터` 같은 조합을 정확히 계산할 수 없어,
> **그레인은 유지하고 기간으로만** 분할했습니다.

## 5. 데이터 스키마

용량을 줄이려고 **컬럼형(배열) + 사전 인코딩**을 씁니다. 금액은 **천원 단위 정수**입니다.

```jsonc
// core.json
{
  "meta":    { "generated": "...", "rules": {...}, "years": [2022, ..., 2026] },
  "dims":    { "ch": ["B2B","온라인","직영","특수"],
               "grp": ["PI","PL","PM","PS","물류","전략","무형","B2B"] },
  "cols":    ["y","m","sd","ch","grp","item","corp","amt","qty","effAmt","sub"],
  "masters": { "items":   [{"code":107,"name":"SBS","grp":"PL","md":"최소라","md_b2b":"손국현","cat":"REF"}],
               "vendors": [{"code":1000003,"name":"엘지전자"}],
               "stores":  [{"code":300010,"name":"용산","jibu":"서울","form":"직영","cls":"POST"}] },
  "rows":    [[2026, 1, 1, 2, 1, 226, 1000003, 10818, 5, 10818, 0]]
}

// year_2026.json
{ "y":2026, "cols":["m","sd","ch","grp","item","corp","store","amt","qty","effAmt","sub"], "rows":[...] }
```

| 필드 | 내용 |
|---|---|
| `sd` | 판매구분 — **1=판매 / 2=매출** |
| `ch` `grp` | `dims` 배열의 **인덱스** · MD는 품목코드+그룹으로 화면에서 역산 |
| `item` `corp` `store` | 품목코드 / 거래선코드 / 지점코드 (원본 코드 그대로) |
| `amt` | 금액 (**천원**, VAT 별도) |
| `qty` | 수량 — **수량제외 품목은 0** |
| `effAmt` | 단가 산정용 금액 (천원) — **수량제외 품목의 금액을 뺀 값** |
| `sub` | 구독 금액 (천원, 매입구분 `E`) |

## 6. 판정 규칙 (집계 단계에서 확정)

### 채널 — 지점코드 우선

```
지점코드 400040            → 온라인
지점코드 302420 · 400041   → 특수
그 외                      → 직영
    └ 직영 중 그룹 = B2B    → B2B
    └ 나머지               → 직영(B2C)

직영計 = 직영(B2C) + B2B
```

지점코드는 일보DB `지점변경` 열로 정규화한 뒤 판정하며, `300015`는 지점변경에 잡히지 않으므로 `300010`으로 별도 통합합니다.

### 그룹 — B2B 먼저 확정

**STEP 1.** 아래 중 하나라도 해당하면 **B2B**

| # | 조건 |
|---|---|
| ① | 거래선코드가 기초DB **AL열 = `B2B`** 목록에 포함 |
| ② | 거래선코드 `1000001`(삼성전자) **AND** 품목코드 ∈ `152,160,510,114,255,256,257,258` |
| ③ | 품목코드 `268`(3D프린터) — 기초DB E열 코드 누락 보정 |

> ⚠ **①의 함정** AK열에 `_` 접두가 붙은 행은 **의도적 표기**이므로 제외합니다. 거래선을 임의로 판단하지 마십시오. 실제로 `1021493`은 숫자행(B2B)과 `_`행(비가전)에 동시 존재하며, **숫자행만** 채택합니다.

**STEP 2.** 나머지는 품목코드(I열) → **E열 그룹코드**

`100=PL` `200=PS` `300=PI` `400=PM` `500=무형` `600=전략` `800=물류`

정렬 순서: **PL → PS → PI → PM → B2B → 무형 → 전략 → 물류**

> F열(그룹명)은 600을 `무형`/`PS`로, 800을 `물류`/`본사`/`온라인`으로 섞어 표기합니다. **반드시 E열 코드 기준**으로 판정하십시오.

### MD

품목코드(I열) → **L열(담당MD 직영)**. 단 **그룹이 B2B면 M열**을 씁니다.
M열 실측: 손국현이 일반 가전 전 카테고리, **한재호가 A/C 계열 전담**. 화면에서는 `B2B_AC`(한재호) / `B2B_가전`(손국현)으로 세분 표기합니다.

### 수량·단가

```
수량      = 기초DB P열 = "X" 품목(악세사리·자재·사은품·설치비·실외기 등)은 합산 제외
유효금액   = 총금액 − (수량제외 품목의 금액)
단가(천원) = 유효금액 ÷ 수량 × 1.1     ← 고객 구매 평단가 인지 목적 (VAT+)
```

실내기 + 실외기 + 조합내기 + 자재 = **1대**로 집계되므로, 자재 금액을 포함한 채 나누면 단가가 부풀려집니다.

## 7. 검증 체크리스트

실 데이터 연동 후 아래를 확인하십시오.

- [ ] 상품축 4개 · 조직축 4개 탭의 **합계가 모두 동일**한가
- [ ] 교차표의 **그룹행 소계 = 하위행 합계**인가
- [ ] **일시불 + 구독 = 금액**인가
- [ ] **단가 × 수량 ÷ 100,000 ÷ 1.1 = 유효금액**인가
- [ ] 추세탭의 월 3개 합 = 분기계, 분기계 4개 합 = 연간계인가
- [ ] 2026 선택 시 7~12월 버튼이 비활성인가 (2026만 1~6월 데이터, 2019~2025는 12개월 전체)

## 8. 알려진 사항

| 항목 | 내용 |
|---|---|
| **채널 vs 그룹 차이** | B2B 그룹 금액과 B2B 채널 금액은 다릅니다. B2B 그룹 거래가 온라인·특수 지점에서 발생하면 **채널은 온라인/특수**로 잡히기 때문입니다 (채널 판정이 우선). |
| **물류 그룹 음수** | 서비스 반품·조정으로 합계가 음수가 될 수 있습니다. |
| **400041** | 2022.07 이후 거래 없으나 코드는 유지합니다. |
| **2026** | 1~6월 데이터만 존재. 년누계 선택 시 가용 월로 자동 축소되고 전년·전전년도 같은 월로 동기 비교합니다. 2019~2025는 12개월 전체. |
| **지점 마스터** | 기초DB를 갱신하면 신규점·변경이 자동 반영됩니다. 온라인(400040)·특수(302420·400041) 지점은 마스터에 없어 채널명으로 라벨링합니다. |
| **동기 비교** | 년누계 선택 시 **해당 연도에 실제 존재하는 월로 자동 축소**되고, 전년·전전년도 같은 월로 비교합니다. 추세탭의 전년比도 공통 존재 월 기준입니다. |
| **목표(예산) DB** | 미보유 — 확보 시 달성율·진척율 KPI 추가 가능. |

## 9. 파일 구성

```
├─ index.html              대시보드 본체 (외부 라이브러리 없음)
├─ README.md               이 문서
├─ .nojekyll               GitHub Pages Jekyll 처리 비활성화
├─ icons/
│   ├─ favicon.ico                     브라우저 탭 (16/32/48 멀티 해상도)
│   ├─ favicon-16x16.png / favicon-32x32.png / favicon-48x48.png
│   ├─ apple-touch-icon.png            iOS 홈화면 추가 (180×180)
│   ├─ android-chrome-192x192.png / android-chrome-512x512.png   안드로이드/PWA
│   └─ site.webmanifest                홈화면 추가 시 이름·아이콘 정의
├─ data/
│   ├─ core.json           코어 큐브 (접속 시 로드)
│   ├─ year_2022_H1.json ~ year_2026_H1.json   연도·반기별 (조직축용, 9개)
│   └─ year_index.json     파일 목록
└─ tools/
    ├─ build_data.py       일보DB + 기초DB → 중간 집계
    └─ build_cubes.py      중간 집계 → 큐브 분리
```

**아이콘 교체** `icons/` 폴더의 6개 PNG(와 favicon.ico)를 원하는 이미지로 덮어쓰면 됩니다. `index.html` 은 수정할 필요 없습니다.

**전체 용량** 약 70.5MB (저장소 권장 한도 1GB 이내)

상세 설계·인수인계 내용은 별도 문서 `판매매출_대시보드_인수인계서`를 참고하십시오.
